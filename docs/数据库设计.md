# 数据库设计

## 1. 设计原则

系统所有业务数据存入MongoDB，不使用关系型数据库。设计按数据生命周期和访问方式拆分集合：问卷、题目、跳转规则、答卷和答案独立保存，避免把持续增长的答卷嵌入单个问卷文档；题目选项和校验条件随题目读取，因此嵌入题目文档。第二阶段新增的题库、题目版本和问卷模板独立于第一阶段集合，保证已有问卷与答卷可以继续使用。

## 2. 集合设计

| 集合 | 主要字段 | 作用 |
| --- | --- | --- |
| `users` | `username`、`passwordHash`、`createdAt` | 账号与认证主体 |
| `surveys` | `ownerId`、`shortId`、`title`、`status`、`allowAnonymous`、`closesAt` | 问卷元信息与发布状态 |
| `questions` | `surveyId`、`order`、`type`、`prompt`、`options`、`validation` | 问卷中的题目快照 |
| `jump_rules` | `surveyId`、`sourceQuestionId`、`targetQuestionId`、`priority`、`condition` | 结构化条件跳转规则 |
| `responses` | `surveyId`、`respondentId`、`anonymous`、`visitedQuestionIds`、`submittedAt` | 一次答卷及实际访问路径 |
| `answers` | `responseId`、`surveyId`、`questionId`、`questionType`、`value` | 一道题的回答，用于聚合统计 |
| `question_banks` | `ownerId`、`name`、`normalizedName`、`sharedWith` | 题目的集合与共享范围 |
| `question_templates` | `rootQuestionId`、`version`、`versionName`、`derivedFromId`、`currentVersionId`、`bankId` | 可复用题目及其版本链 |
| `survey_templates` | `ownerId`、`title`、`questions`、`jumpRules` | 整份问卷模板快照 |

## 3. 嵌入与引用

`surveys.ownerId`、`questions.surveyId`、`responses.surveyId`和`answers.responseId`使用ObjectId引用，避免复制用户和问卷元信息。`questions.options`和`questions.validation`嵌入题目，因为选项、长度限制、数值范围和多选数量限制都随单题配置读取。`jump_rules`独立保存，便于一个来源题设置多条按优先级匹配的规则。

答卷头`responses`与答案`answers`拆分，统计时能按问卷或题目聚合，且不会持续扩张单个文档。`responses.visitedQuestionIds`保存服务端重算后的路径，用于区分已访问、被跳过和访问后未答。

## 4. 第二阶段版本与快照

一个逻辑题由`rootQuestionId`标识，每次编辑创建新的`question_templates`文档，并记录`version`、`versionName`和`derivedFromId`。`currentVersionId`只表示当前选中的版本；回溯只更新该指针，不复制新版本。每个逻辑题最多保留10个版本。

问卷中的`questions`保存题目快照，并记录`sourceTemplateId`和`sourceTemplateVersion`。因此题库版本后来变化时，已经创建或发布的问卷内容、答卷语义和统计不会改变。删除整题前服务端检查所有版本是否被问卷快照引用；被引用则拒绝删除。

`survey_templates`嵌入题目与规则快照。基于模板新建时将快照复制到新的`surveys`、`questions`和`jump_rules`文档，模板、源草稿和新草稿的生命周期相互独立。

## 5. 索引与一致性

初始化脚本为用户名、问卷短链接、问卷所有者、题目题序、规则优先级、答卷与答案查询、题库名称和题目版本建立索引。其中`question_banks(ownerId,normalizedName)`为唯一索引，拒绝同一用户创建同名题库；`question_templates(rootQuestionId,version)`约束版本号唯一。

MongoDB集合之间没有外键，因此服务端在写入前检查所有者、模板权限和引用存在性。删除问卷时按答案、答卷、规则、题目、问卷的顺序清理关联文档；跨集合写入失败时采用补偿处理。完整字段、validator和索引定义见`db/init.js`。
