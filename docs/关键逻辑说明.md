# 关键逻辑说明

## 1. 题目版本、分支与回溯

题目版本不等同于新题目。新建题目时生成新的`rootQuestionId`和第1个版本；编辑同一题目时，以当前版本为来源生成下一个版本，保留`derivedFromId`。同一个逻辑题最多保留10个版本。用户可填写版本名称、查看历史版本详情和直接来源。

回溯到历史版本只把该逻辑题的`currentVersionId`切换为目标版本，不创建副本，也不删除其他分支。随后再编辑会以当前版本为来源创建分支。复制题目则创建新的`rootQuestionId`，与原题目版本链完全独立。

问卷加入题目时复制具体版本内容为`questions`快照，记录来源ID和版本号。这样版本变化不会改变既有问卷或已提交答卷。删除整题或单个版本前检查所有问卷快照引用，避免破坏历史问卷和统计。

## 2. 跳转设计

跳转规则是独立的`jump_rules`文档，包含来源题、目标题、优先级和结构化条件。条件不保存可执行代码，而是保存题型、运算符和操作数：单选按选项匹配，多选按包含关系或选择数量匹配，数字题按大小或区间比较。

填写时先按题序读取当前题，再按优先级匹配当前题规则；首条匹配规则决定下一题，无匹配时进入下一题。发布前服务端检查“规则边+默认顺序边”构成的图是否有循环；提交时服务端依据实际答案重新计算访问路径，拒绝循环、伪造路径和与规则不一致的答案路径。

## 3. 校验设计

题目配置中的`required`、`validation`和`options`驱动校验，不将数值范围、字数或选项限制写死在页面代码。前端根据配置即时提示，服务端在提交答卷时再次执行相同语义的校验。

单选题必须选择已定义选项；多选题检查选项有效性以及最小、最大或固定选择数量；文本填空检查必答、最小和最大长度；数字填空检查数值类型、最小值、最大值和整数要求。服务端还验证问卷已发布、未截止、匿名与重复填写设置，以及答卷是否包含被跳过题目的答案。

## 4. 统计与使用关系

统计不维护可失真的题目计数器，而是从`responses`和`answers`事实数据实时聚合。选择题统计每个选项次数；文本题列出答案；数字题计算平均值。根据`visitedQuestionIds`可额外统计已访问、被跳过和访问后未答。

跨问卷统计根据问卷题目快照的`sourceTemplateId`定位同一题目版本，聚合所有已提交答卷。题目使用关系同样通过该来源字段查询，不依赖前端缓存。

## 5. 题库、问卷库与删除保护

题库是题目的集合，不是单个隐藏字段。题库按所有者和规范化名称唯一，题目管理页与问卷选题器都可按题库筛选。服务端在题目复用时验证所有者、题目共享或题库共享权限。

问卷库保存整份草稿的题目和规则快照，使用模板时复制为新的问卷草稿。删除模板不会影响已复制问卷；删除问卷会按答案、答卷、规则、题目和问卷顺序删除关联记录。跨集合操作均有服务端检查，避免产生孤立的业务数据。

## 6. 功能验证与测试数据

工作台“功能验证”通过真实管理接口创建`测试用功能验证`问卷、题库和题目版本，并在同源`iframe`中操作真实填写页，以验证跳转。随后验证非法答案拒绝、合法提交、统计和题库版本行为。每一步展示请求、响应和断言证据。测试数据保留供人工检查，点击“一键删除测试数据”后删除；若浏览器残留的测试标记指向已不存在的数据，前端会自动清除旧标记。

命令行`npm run verify`和`npm run verify:phase2`使用独立临时数据，并在结束时仅清理各自创建的数据。测试用例与实际结果见[实验报告.md](实验报告.md)第8节。
