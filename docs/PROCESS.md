## 3. 集合划分及嵌入/引用决策

| 决策点 | 备选方案 | 选择与理由 |
|---|---|---|
| 用户与问卷 | 问卷嵌入完整用户 / `ownerId` 引用 | 引用 `users._id`。用户与问卷是独立生命周期，一用户多问卷；避免账号资料重复和同步更新 |
| 题目 | 所有题嵌入 survey / 独立 `questions` | 独立集合。题目可单题查询/统计，问卷题目数量可增长；survey 文档保持小且编辑冲突减少 |
| 选项 | 独立集合 / `questions.options` 嵌入数组 | 内嵌。选项有限且和题目一起读写，稳定 key 可被答案/规则引用；少一次查询与维护成本 |
| 校验配置 | 独立集合 / `questions.validation` 子文档 | 子文档。规则归属题目，原子读取编辑；按题型解释字段和值，不将业务数值写死 |
| 跳转规则 | 放在源题目 / 独立 `jump_rules` | 独立集合。支持一题多条、优先级、独立扩展查询，避免题目文档膨胀与题型耦合 |
| 答卷答案 | 答案数组嵌入 response / 独立 `answers` | 独立集合。单题聚合便利，避免数组增长和同一答卷文档并发写争用；以索引保证当前答案唯一 |
| 问卷统计 | 写入时维护计数 / 实时从 answers 聚合 | 实时聚合。避免答案与计数双写不一致，初期负载下结构简单；未来可增加可重建派生统计 |

## 4. 冗余设计清单

| 位置 | 内容 | 理由 | 一致性维护 |
|---|---|---|---|
| `answers.surveyId` | 由 response/question 可推导的问卷 ID | 统计查询少一次跨集合关联 | 写入时校验三者归属一致；survey 归属不可变；定期巡检 |
| `answers.questionType` | 作答时题型快照 | 保留解释上下文，避免题型修改后历史值误读 | 有答案题禁止改变题型，或以新问卷版本承载修改 |
| `answers.questionOrderSnapshot` | 可选作答时顺序快照 | 历史上下文/审计 | 写入时复制；只读快照 |
| 无统计计数器 | 无 | 降低一致性成本 | 每次查询以答案与已提交答卷为事实来源；必要时重算 |

## 5. 数据驱动配置说明

- 校验规则由 `questions.required` 与类型化 `validation` 子文档表达：多选 min/max；文本 min/max length；数字 min/max/integerOnly。提交服务按配置执行，不在代码放业务阈值。
- 跳转条件由 `jump_rules.condition` 的 answerType/operator/optionKeys/value/min/max 表达，目标、顺序和启用状态也是数据。只解释允许的运算符，禁止执行任意代码文本。发布时把可能命中的规则边与未命中时的顺序边一并检查，发现循环即拒绝发布并保留草稿；填写时继续检查重复访问作为防护。
- 后续修订：答卷提交时服务端依据答案与启用规则重建实际访问路径，并写入 `responses.visitedQuestionIds`。统计据此分别返回已回答、已访问、被跳过和访问后未答；缺少该字段的历史答卷不推断路径。
- 全量配置样例见 `STRUCT.md` 对应章节；`db/init.js` 提供 MongoDB 核心字段类型/必填约束。

## 7. 待确认问题

- “填写者需要先登录”与“允许匿名填写”如何协调？当前方案假定必须通过登录访问，但匿名答卷不关联用户 ID；若匿名意为未登录公开填写，认证策略需调整。
- 匿名答卷在禁止重复时使用问卷作用域 HMAC 去重键，不保存可反查账号的身份信息；应用密钥应在部署期间保持稳定。
- 问卷发布后是否允许编辑？若允许，已提交答案的题目/选项和规则是否要完整保留版本？建议发布版本不可变，修改后形成新版本。
- 题目跳转允许跳回/循环吗？当前建议发布时检测并拒绝循环，运行时也需防护。
- 用户名是否大小写不敏感；手机号格式是否需要国家区号/正则规则；本文把手机号校验作为未来可扩展文本规则。
- 本机 MongoDB 是否配置副本集？若需要原子提交跨集合事务，需单节点副本集或部署支持事务的副本集。

## 8. 复现与验证记录

脚本执行方式为 `.env` 配置 `MONGODB_URI`、`MONGODB_DB` 后运行 `npm.cmd ci`、`npm.cmd run db:init`、`npm.cmd start` 和 `npm.cmd run verify`（macOS/Linux 可用 `npm`）。`db:init` 不清空数据；`verify` 会连接配置的服务与数据库并创建/清理临时记录，应使用专用测试库。已有集合应用 `collMod` 升级 validator，已有索引冲突时初始化会失败并需人工处理。
